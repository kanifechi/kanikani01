# stock_warehouse — 日本株データの倉庫（仮想データ版）

株価データを **3段** に分けて保存する、研究所の自前の倉庫です。

| 段 | 中身 | 置き場所 | 形式 |
| --- | --- | --- | --- |
| 1段目 生データ | 銘柄ごとの日足（日付・始値・高値・安値・終値・出来高・分割倍率） | `data/<取り口>/raw/<code>.csv` | CSV |
| 2段目 計算済みの数字 | 前日比・移動平均・ATR などを1段目から計算した物 | `data/<取り口>/features/<code>.csv` | CSV |
| 3段目 判定用カード | 1銘柄1枚の短い要約（Jev に渡す用、8KB以下） | `data/<取り口>/cards/<日付>/<code>.json` | JSON |

いまのデータは **すべて仮想データ（架空の銘柄 9901〜9920 と架空の市場指数 9999）** です。
データの取り口（どこから株価を持ってくるか）は1つの部品にまとめてあるので、あとで本物のAPIに差し替えられます。

> ⚠️ 投資助言ではありません。仮想データの数字は実在の銘柄と関係ありません。

---

## 1. 動かす

```bash
cd stock_warehouse
pip install -r requirements.txt          # pandas / numpy / jsonschema

python -m warehouse                       # 仮想データで全期間を作る（1段目→2段目→3段目、数秒）
python -m warehouse --date 2026-10-30     # その日の分だけ更新する
python -m unittest discover -s tests -v   # テスト（ネット接続なしで動く）
```

実行すると、最後にこう表示されます：

```
基準日 2026-10-30: 1段目 21銘柄 / 2段目 21銘柄 / カード 20枚 → .../data/virtual/cards/2026-10-30（カードなし: 9920）
```

（9920 は途中で上場廃止になる設定なので、最終日のカードはありません。）

### オプション

| オプション | 意味 |
| --- | --- |
| `--source virtual` / `--source csv` | データの取り口（既定は virtual） |
| `--csv-dir フォルダ` | CSVの取り口のとき、CSVを置いたフォルダ |
| `--seed 数字` | 仮想データの乱数の種（既定 20261102）。同じ種なら毎回まったく同じ結果になります |
| `--date YYYY-MM-DD` | その日の分だけ取り口から読み、1段目に足して2・3段目を作り直す |
| `--start` / `--end` | 全期間作り直しのときの期間 |
| `--data-dir フォルダ` | 出力先（既定は `data/<取り口の名前>`。仮想と本物が混ざらないよう分けています） |
| `--quiet` | 進み具合を表示しない |

カードが1枚もできなかったとき（休場日を `--date` で指定した等）は、終了コード 1 になります。

## 2. CSVで本物のデータを試す

1. フォルダを1つ作り、**1銘柄1ファイル** でCSVを置きます。ファイル名が銘柄コードになります（例 `7203.csv`、`130A.csv`）。
2. 列は1段目と同じです（順番は自由、大文字小文字も可）：

   ```csv
   date,open,high,low,close,volume,split_ratio
   2026-10-29,2850,2875,2840,2862,12345600,1
   2026-10-30,2870,2890,2855,2880,11002300,1
   ```

   - `date`：`2026-10-30` または `2026/10/30`
   - 価格：**分割調整していない、その日の実際の値段**
   - 取引が成立しなかった日：`open,high,low,close` を空欄、`volume` を `0`
   - `split_ratio`：省略可（省略すると「分割なし」）。分割があった銘柄は、**分割の効力発生日の行に倍率**（1→2 なら `2`）を入れます。
     **分割前後の生の価格だけを入れて split_ratio を書かないと、価格が飛んだまま計算されます。**
   - 文字コードは UTF-8（Excel の「CSV UTF-8」で保存した BOM 付きも可）
3. 任意で `instruments.csv` を置くと、銘柄名と種類を指定できます。市場全体の指標（TOPIX など）は `kind` を `index` にしてください（カードの `market` 欄に使われます）：

   ```csv
   code,name,kind
   7203,トヨタ自動車,stock
   TOPIX,TOPIX,index
   ```

4. 実行します：

   ```bash
   python -m warehouse --source csv --csv-dir ~/my_prices
   # → data/csv/raw, data/csv/features, data/csv/cards/<最終日>/ ができます
   ```

形がおかしいCSV（列が足りない・高値が安値より低い・日付の重複など）は、理由を表示して止まります。
休場日の行があるときは止まらずに「注意」を表示します。

ためしに、仮想データの1段目（`data/virtual/raw/`）をそのままCSVの取り口に読ませることもできます。結果は仮想データ版と同じになります（テストでも確かめています）。

## 3. 本物のAPIに差し替える

ほかの部品（2段目・3段目・コマンド）は **取り口の中身を知りません**。`warehouse/sources/base.py` の `DataSource` の約束だけを使っています。差し替えで書くのは、次の **1ファイルと1行** だけです。

### 手順

1. `warehouse/sources/` に新しいファイル（例 `jquants.py`）を作り、`DataSource` を継承したクラスを書きます。

   ```python
   from .base import DataSource, Instrument, RAW_COLUMNS, empty_raw_frame, read_secret

   class JQuantsSource(DataSource):
       name = "jquants"                       # カードの source 欄・出力フォルダ名になる

       def __init__(self):
           self.token = read_secret("JQUANTS_REFRESH_TOKEN")  # キーはコードに書かず環境変数から

       def list_instruments(self) -> list[Instrument]:
           # 扱う銘柄の一覧。市場全体の指標は kind="index"
           ...

       def fetch_daily(self, code, start=None, end=None):
           # API を呼んで、RAW_COLUMNS の DataFrame を返す
           ...
   ```

2. `fetch_daily` が返す DataFrame の **約束**（`base.py` の冒頭にも書いてあります）：

   | 約束 | 中身 |
   | --- | --- |
   | 列 | `date, open, high, low, close, volume, split_ratio`（この順番） |
   | date | `"YYYY-MM-DD"` の文字列、昇順、重複なし |
   | 価格 | **分割調整前**の実際の値段。API が調整後の値しか返さない場合は、調整前に戻すか、`split_ratio` を全部 1 にして「調整済みの値」として入れる（そのときストップ高・安の判定は過去分がずれる） |
   | 取引不成立 | 四本値は NaN、volume は 0 |
   | split_ratio | 分割の効力発生日に倍率（1→2 なら 2.0）、それ以外は 1.0。API の「調整係数」が 0.5 のような形なら `1 / 係数` |
   | データ無し | 列だけそろった空の DataFrame（`empty_raw_frame()`） |

3. `warehouse/sources/__init__.py` の `make_source()` に1行足し、`SOURCE_NAMES` に名前を足します。

   ```python
   if name == "jquants":
       return JQuantsSource()
   ```

4. テストを足します。ネットにつながずに済むよう、API の返事を小さなファイルに保存して読ませる形にします（`tests/test_pipeline.py` の `SwapSourceTest` が「取り口を替えても動く」ことの見本です）。
5. 動かします：`JQUANTS_REFRESH_TOKEN=... python -m warehouse --source jquants`

取り口から来たデータには、どの取り口でも同じ点検（`warehouse/validate.py`）がかかります。約束と違う形なら、2段目に入る前に止まります。

### 秘密（APIキー）の扱い

- キーはコード・ファイル・コミットに **書きません**。`read_secret("名前")` で環境変数から読みます（無ければ分かりやすいエラーで止まります）。
- ローカル：`export JQUANTS_REFRESH_TOKEN=...`
- GitHub Actions：リポジトリの Settings → Secrets and variables → Actions に登録し、ワークフローで `env: JQUANTS_REFRESH_TOKEN: ${{ secrets.JQUANTS_REFRESH_TOKEN }}` として渡します。

### 自動実行（今回は作っていません）

本物の取り口ができたら、GitHub Actions に **毎日夕方（大引け後のデータがそろう時刻）に `python -m warehouse --source <名前> --date <今日>` を動かす設定** を足します。

## 4. 決めごと（どう計算しているか）

### 株式分割：調整後の価格で計算する

- **1段目は「その日の実際の値段」と分割倍率をそのまま保存** します（取り口から来たままの形）。
- **2段目・3段目は分割調整後の値で計算** します。調整は「後ろから」：分割より前の価格を倍率で割り、出来高を倍率で掛けます。
  - 最新日の調整後の価格は、その日の実際の値段と同じです。
  - 新しい分割が起きると、過去の調整後の価格が変わります。そのため2段目は、`--date` の更新でも **毎回その銘柄の全期間を計算し直し** ます（数秒で終わります）。
  - 2段目の `adj_factor` が「その日の実際の値段 ÷ 調整後の値段」です。
- ストップ高・ストップ安の判定だけは、実際の値段で行います（制限値幅は実際の値段で決まるため）。分割の日の基準値段は、前日終値 ÷ 倍率を1円単位に丸めた物です。

### データが足りない日・取引が成立しなかった日

- 移動平均200日なら、取引が成立した日が200日そろうまで **空（null）** にします。前の値で埋めたり、短い期間で代わりに計算したりはしません。ほかの数字も同じです。
- 「N日」は **取引が成立した日をN回** 数えます（取引不成立の日は飛ばします）。
- 取引不成立の日（出来高0、四本値なし）は、その日の価格の数字をすべて空にします。翌日の前日比は「最後に成立した日の終値」と比べます。
- 出来高の数字（20日平均・倍率）は、不成立の日も **出来高0として含めます**（0は本当の値なので）。

### 2段目の列

| 列 | 意味 |
| --- | --- |
| `no_trade` | 取引不成立の日なら True |
| `split_ratio`, `adj_factor` | 分割倍率、調整の割り算に使った数 |
| `open_adj` 〜 `volume_adj` | 分割調整後の四本値・出来高 |
| `sessions` | その日までの取引成立日数 |
| `change_pct` | 前の成立日の終値からの変化率（%） |
| `ma5, ma25, ma75, ma200` | 終値の単純移動平均 |
| `close_vs_maN_pct`, `above_maN` | 終値が移動平均から何%離れているか、上にあるか |
| `ma_alignment` | `bull`（5>25>75）、`bear`（5<25<75）、`mixed` |
| `volume_avg20_prev`, `volume_ratio20` | 前日までの20日の出来高平均、その日の出来高 ÷ それ |
| `high20_prev`, `low20_prev` | 前日までの20成立日の最高値・最安値 |
| `new_high20`, `new_low20` | その日の高値（安値）が上の値を上回った（下回った） |
| `tr`, `atr14`, `atr14_pct` | 真の値幅、ATR 14日（ワイルダー方式：最初は TR 14本の単純平均、以降 (前日ATR×13+TR)/14）、ATR ÷ 終値 |
| `limit_base`, `limit_width` | 値幅制限の基準値段と制限値幅（東証の通常の表） |
| `limit_up`, `limit_down` | ストップ高（安）で引けた |
| `limit_up_touched`, `limit_down_touched` | 高値（安値）がストップ高（安）に届いた |

市場全体の指標（kind=index）には値幅制限の列は入りません（空）。

### 3段目（判定用カード）

- 形は `warehouse/schemas/card.schema.json`（JSON Schema 2020-12）で決めています。作るたびにスキーマと **8192バイト以下** を確かめ、外れたら止まります。
- 中身：`latest`（基準日まででいちばん新しい成立日の値）、`recent`（直近10日の流れ）、`trend`（5日・20日の変化、上げ下げの日数、ストップ高・高値更新の回数）、`market`（同じ日の市場全体の指標）、`data.notes`（なぜ null なのか等の注意書き）。
- 基準日に行が無い銘柄（上場前・上場廃止後）のカードは作りません。基準日が取引不成立の銘柄は、`data.no_trade_today: true` のカードを作り、`latest` は最後に成立した日の値にします。

## 5. 仮想データの「意地悪」

本物を入れたときに壊れないよう、わざと混ぜてあります（日付は種に関係なく固定、値動きだけ種で変わります）。

| 事情 | 銘柄・日付 |
| --- | --- |
| 土日・祝日・年末年始は取引なし | 全銘柄（2024-11-01〜2026-10-30、485営業日） |
| 株式分割 | 9905：2025-07-01 から 1→2 ／ 9912：2026-04-01 から 1→3 |
| ストップ高・ストップ安 | 9903：2025-03-10・11 連続ストップ高 ／ 9908：2026-02-16 ストップ安 ／ 9914：2026-10-28 ストップ高（ほかに自然に当たる日もあり） |
| 出来高0（取引不成立） | 9917：2025-05-14、2025-12-03、2026-10-29 |
| 途中から上場 | 9919：2026-03-02 から（最終日でも200日線は null） |
| 途中で上場廃止 | 9920：2025-12-26 が最後 |
| 市場全体の指標役 | 9999（出来高は全銘柄の合計） |

## 6. フォルダ構成

```
stock_warehouse/
├── README.md
├── requirements.txt
├── warehouse/
│   ├── __main__.py        コマンド（python -m warehouse）
│   ├── pipeline.py        通し：取り口 → 1段目 → 2段目 → 3段目
│   ├── sources/
│   │   ├── base.py        ★ 取り口の約束（DataSource）と read_secret
│   │   ├── virtual.py     仮想データの取り口
│   │   ├── csv_source.py  CSVの取り口
│   │   └── __init__.py    取り口の一覧（make_source）
│   ├── validate.py        1段目の点検
│   ├── features.py        2段目の計算
│   ├── cards.py           3段目のカード作り
│   ├── schemas/card.schema.json
│   ├── calendar_jp.py     日本の祝日・東証の休場日（2022〜2099年）
│   └── market_rules.py    値幅制限の表
├── tests/
│   ├── test_calc.py       計算を手計算の例と突き合わせ、祝日・点検
│   └── test_pipeline.py   再現性・意地悪なデータ・スキーマ・取り口の差し替え・日付指定の更新
└── data/virtual/          仮想データで作った結果（raw / features / cards）
```

## 7. 分かっている限界

- 祝日は現行の祝日法の規則で計算しています（2022〜2099年）。今後の法改正や、東証の臨時休場は反映されません。本物のデータでは「データが無い日」として現れるだけなので、計算は壊れません。
- 値幅制限は東証の通常の表だけです。制限値幅の拡大、上場初日の扱い、0.1円刻みの銘柄の細かい扱いは入れていません。
- 分割以外の権利（併合・無償割当・配当落ち）は扱っていません。併合は `split_ratio` に 1 未満（1/10 併合なら 0.1）を入れれば同じ仕組みで調整できますが、テストはしていません。
